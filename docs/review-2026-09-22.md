## Open findings

The two P1 findings below remain open at the user's request. The three P2
findings were subsequently fixed and are tracked separately below. Original
reproductions and rationale are retained for context. Priorities reflect
behavioral impact, not a claim that every deployment encounters the trigger.

### P1: Tool iteration limits do not prevent dispatch

Location: `agentflow/lite/agent.py:132-153`; introduced in `1a16b49`.

When the tool budget is exhausted, `_chat` omits the advertised tools, but `_run`
still dispatches any tool calls returned by the provider. A compatible provider
returning tool calls despite the omission can execute registered tools beyond
the configured limit. An httpx.MockTransport reproduction with
`max_tool_iterations=0`, `max_iterations=2` and two tool-call responses executed
the handler twice and returned `finish_reason="max_iterations"`.

Enforce the limit immediately before dispatch, independently of the provider.
Reject or return a structured budget result for those calls. Withholding tool
schemas remains useful prompting, but does not enforce a runtime budget.

### P1: Invalid scorer results can become winning scores

Location: `agentflow/graph_optimizer.py:285-309`; introduced in `74dc817`.

`compute_run_score` ignores the subprocess exit code and accepts non-finite
floats. Mocking exit code 1 with stdout `100` returned `100.0`; stdout `nan` with
exit code 0 returned NaN. Exceptions instead become `0.0`, losing the distinction
between a valid zero score and an evaluation failure. These results feed the
incumbent comparison and persisted optimization events.

Require successful execution, a documented numeric output contract, and a finite
value. Persist a scoring error separately and exclude invalid rounds from
selection. A failed evaluator must not produce an apparently superior candidate.
The shell command is explicitly author-configured; use of a shell alone is not
the defect identified here.

## Resolved P2 findings

Locations below refer to the originally reviewed revision; each entry records
the original behavior followed by the implemented resolution.

### P2: All non-positive scores bypass incumbent selection — fixed

Location: `agentflow/orchestrator.py:395,495-499,689-696`; introduced in `74dc817`.

Original behavior: the incumbent started at `0.0` and changed only for a strictly
higher score.
Command scores are not constrained to positive numbers. For valid round scores
`-1` followed by `-10`, neither round sets `best_pipeline`; the final fallback
selects the last, worse pipeline. All-zero rounds likewise produce no recorded
best round despite having valid candidates.

Resolution: an absent `best_pipeline` now causes the first scored candidate to
be selected regardless of score sign. Later candidates replace it only for a
strictly higher score, retaining the first round on ties. Integration regressions
cover decreasing and increasing negative scores, all-zero ties and a negative
score followed by zero; they verify session metadata, selected pipeline and the
saved best-pipeline artifact. Scorer validity and the existing run-status policy
remain separate concerns; the P1 scorer finding is still open.

### P2: Failed container removal is reported as successful — fixed

Location: `agentflow/lite/container.py:108-118`; introduced in `c7f9d35`.

`docker rm -f` normally reports daemon/permission failures through a nonzero exit
code. The original `_force_remove` handled invocation exceptions but discarded the completed
process status. A mocked removal returning code 1 and `daemon unavailable` still
produced `[container mock-name force-removed after timeout]`. A timeout can thus
leave work running while reporting cleanup success.

Resolution: `_force_remove` checks the subprocess return code. Nonzero exits
produce a warning with the exit code and at most 1,000 characters of stderr
(or an explicit missing-diagnostic message). Successful removal retains the
success message, and invocation errors retain their existing warning behavior.
Mocked timeout regressions cover daemon failures, absent diagnostics and long
stderr while checking that partial command output remains available.

### P2: Log windows are not bounded in bytes — fixed

Location: `agentflow/store.py:129-150`, `agentflow/app.py:96-105`; introduced in
`a6a7701`.

The original backward reader stopped after enough newline delimiters, not after
a byte budget. A temporary 2 MiB single-line file requested with `limit=1` returned all
2,097,152 bytes. Larger newline-free stdout or large JSONL records can grow this
without a cap. Repeated prepending and newline counting also reprocess the growing
buffer. The original async HTTP handler performed this synchronous read on the event loop.

Resolution: each page reads at most 64 KiB of content plus one lookbehind byte.
A single bounded buffer replaces the repeated prepend/count loop. Oversized
records continue across pages using `before` and `end` source-byte cursors;
`partial_start` and `partial_end` identify the first and last record fragments.
Valid UTF-8 characters and CRLF pairs remain on the same page. The monitor labels
fragments and displays partial trace records as raw text instead of attempting
JSONL interpretation. The synchronous FastAPI handler runs file reads and response
construction in the worker thread pool, outside the HTTP event loop.

Regression coverage includes a 2 MiB line, each alignment of four-byte UTF-8
characters, CRLF at the byte boundary, complete records under a line limit,
actual read-size bounds, off-event-loop execution, and visible browser fragment
labels. Existing Unicode/blank-line/append-cursor tests remain in place.

## Deferred observations

SSE still rereads and reparses the entire event file every 0.5 seconds. Maintaining
a file offset could avoid work proportional to all historical events on each
poll; this remains recorded without implementation or throughput claims.

The byte cap bounds each response's source content, not the whole browser session
or arbitrary full-artifact downloads. Readers can still accumulate history by
requesting additional pages. JSON escaping and invalid-UTF-8 replacement can make
the encoded response larger than the source-byte limit. These distinctions are
part of the API contract, not claims of a global memory or bandwidth budget.


## Feature value and architecture decisions

| Addition | Assessment |
| --- | --- |
| Default/full graph projection | Keep. A default focused view and an explicit complete view serve different inspection tasks. The old reached-only initial view concealed the workflow until users discovered the toggle. |
| Activation gates, failure edges, all-done joins, hybrid nodes | Keep as optional composition mechanisms. Fixed-capacity activation is not arbitrary runtime graph growth; the documentation makes that distinction. |
| Controller receipts and graph-owned action limits | Keep. They record decisions and scope authority without embedding application roles. They are not transactional crash recovery or proof of completed work. |
| Process supervision, cancellation and container cleanup | Keep. These solve concrete lifecycle problems, with truthful cleanup failure reporting now implemented. |
| Lite client, tools, router and graph runner | Keep as a separately documented execution model. It serves direct HTTP/tool use while core wraps CLI agents. Two implementations impose maintenance cost, but are not inherently meaningless duplicates; AGENTS.md intentionally requires independence. |
| Request, resource and tool concurrency budgets | Keep their distinct scopes explicit. Request capacity, node resource leases and tool read/write coordination limit different resources. They do not constitute a token/cost budget or an isolation boundary. |
| Tool/token limits | Useful, but distinguish enforcement from prompting and accounting. Tool dispatch needs the P1 fix. Token accounting currently happens after a response, so a single request can overshoot the configured threshold; do not describe it as a hard provider spending cap. |
| Graph optimizer, diagnosis and archive | Optional experimental functionality. Retain only with honest evaluation semantics; incumbent selection is corrected, while scorer validation remains open. There is no task-quality benchmark here establishing that these mechanisms improve results. |
| Longest-path progress | A structural stage metric, not percentage of work or success. A completed longest branch can reach the denominator while a shorter independent branch still runs. Keep run status visible and avoid presenting the number as an overall completion guarantee. |
| Actor/profile/extension/Terminus abstractions | Recognize the upstream import rather than attributing it to this fork. Keep optional; no application role catalog or mandatory collaboration sequence is justified. Live Harbor execution was not tested. |
| Paper/method workflow examples | Useful as structural examples, not validated reproductions of published systems. Prompt-only approval/oracle/evidence steps do not enforce those capabilities; retain readiness and fidelity labels. |
| Paper fidelity models in `agentflow/lite/fidelity.py` | Candidate for relocation to optional example tooling. These paper-specific models are eagerly re-exported by the lite runtime package despite being corpus validation concerns. This is avoidable framework surface, not an urgent runtime bug; preserve compatibility if moved. |
| Read-only monitor and paginated artifacts | Keep. Reading persisted state supports separate CLI producers. Log pages now have byte bounds; incremental event reads remain deferred. |
| Fixed theme, custom layout and historical screenshots | Product choices, not intrinsic best-practice violations. Existing CSS and JS style injection create multiple styling owners; consolidation is a maintenance opportunity, not grounds for deleting useful UI features. |

No basis was found for deleting all fork features or merging the two execution
models indiscriminately. The actionable problems are unenforced contracts,
incorrect evaluation/cleanup claims, unbounded monitoring work, and domain-specific
example concerns exposed as general runtime API.
