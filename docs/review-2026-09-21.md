## Framework freedom and ownership

No reviewed runtime code contains the authoring application's fixed role set,
slot topology, handoff filenames, or delivery acceptance gate. These remain in
`xpertAuthorFlow/authoring_workflow`. In particular:

- ActorNode is optional and caller-subclassed; it contains no built-in business
  roles, objectives, reviewer requirement, or prescribed planning sequence.
- Plain Graph/NodeSpec/agent/shell usage does not require actors or profiles.
  Neither artifact metadata nor a profile installs workflow-specific gates.
- Work-item identity, session identity, tree hashing, and process cleanup are
  reusable lifecycle mechanisms. Session roles are arbitrary caller strings;
  traversal exclusions are caller arguments.
- Periodic action scope, allowed actions, and optional rerun limits come from
  the submitted graph. The framework's rerun cap defaults to unset. The value
  100 belongs solely to the authoring application's configuration.
- Built-in adapter capability checks represent supported CLI/backend features.
  Docker secret-file requirements are an execution/credential policy, not a
  business-role policy. They are a compatibility change from the older fork,
  documented in the upstream sync, not a new universal sandbox guarantee.
- Existing domain graph examples remain opt-in examples. They are not imported
  into the scheduler as default workflows. No new application role catalog,
  role router, or release policy was added in this review.

The framework supplies primitives and faithful results; callers supply goals,
collaboration topology, prompts, tools, evaluation criteria, and policy values.
This ownership rule is now explicit in AGENTS.md.

## Design evidence and limits

[Anthropic's Building effective agents](https://www.anthropic.com/engineering/building-effective-agents)
recommends simple composable building blocks and distinguishes predefined
workflows from agent-directed execution. Our inference is to keep both choices
available to applications rather than mandate a collaboration pattern.

[Anthropic's Managed Agents architecture](https://www.anthropic.com/engineering/managed-agents)
separates session, harness, and sandbox responsibilities. This supports the
separation of execution state from model behavior; it does not establish that
AgentFlow's same-user deployment provides an equivalent isolation boundary.

[The MCP tools specification used by this application](https://modelcontextprotocol.io/specification/2025-06-18/server/tools)
describes tool schemas, structured results, and error signaling. Such interfaces
do not by themselves authenticate authority or ensure that a model calls a tool.
A native-tool/MCP choice is therefore an integration decision; no transport is
claimed universally superior to skill+Bash without a controlled model experiment.

Remaining limits: scheduler receipts describe cancellation requested or rerun
queued, not task success. Replay suppression has documented run/controller/
action/target scope; batches and crash recovery are not transactional. Same-UID
state is not tamper-proof, container marker files are not attestations, and retry
counts are not token/cost budgets. These are deployment or future reliability
concerns, not reasons to embed application roles in the framework.
